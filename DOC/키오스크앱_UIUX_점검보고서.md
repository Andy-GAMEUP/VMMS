## 2. 발견 이슈 (심각도순)

### 🔴 치명 (Blocker) — 기능/판매 직접 저해

**F-1. 상품 카드 탭이 상세로 진입하지 않음** *(실측)*
- 상품 카드 여러 위치를 탭해도 상세 화면으로 전환되지 않고 상단 배너만 자동 회전.
- 프리뷰 스케일 영향일 수 있으나, 키오스크에서 상품 탭 → 상세 진입은 **핵심 구매 동선**. 반드시 실기기 검증 필요.
- **조치**: 카드 전체를 탭 타겟으로 지정, 탭 시 명확한 눌림 피드백(`active:scale`), 상세 라우팅 연결 확인.

**F-2. 하단 상태바(기기정보/고객서비스/언어) 탭 무반응** *(실측)*
- 하단 상태바 항목 탭이 모달을 열지 않음(프리뷰 기준). 관리자 진입(기기정보 5회 탭)까지 이어지는 경로이므로 실기기 검증 필수.

### 🟠 중요 (High) — 사용성 저하

**H-1. 텍스트 크기 / 시야거리** *(실측)*
- 상품명·가격·카테고리 라벨이 키오스크 표준 시야거리(50~80cm) 대비 작음.
- **조치**: 상품명 ≥ 28px, 가격 ≥ 32px, 카테고리 라벨 ≥ 22px 등 하한 재설정(1080px 기준).

**H-2. 배너 자동회전 속도** *(실측)*
- 터치 없이도 배너가 빠르게 전환되어 상품 탐색 중 시선 분산.
- **조치**: 전환 주기 6~8초로 완화, 사용자 탭 시 자동회전 일시정지, 인디케이터/좌우 수동 이동 제공.

**H-3. 무조작 복귀(타임아웃) 정책 미확인** *(스펙 미명시)*
- 장바구니에 담긴 채 이탈 시 개인정보/오조작 방지를 위한 대기화면 자동 복귀 필요.
- **조치**: 60~90초 무조작 시 "계속하시겠어요?" 확인 후 대기화면 복귀 + 장바구니 초기화.

**H-4. 관리자 진입 방식** *(실측)*
- 기기정보 모달 푸터에 "관리자 진입: 제목 5회 탭" 명시 확인. 숨김 제스처로 편리하나 인증 없음 시 오남용 위험.
- **조치**: 5회 탭 후 PIN/비밀번호 1단계 추가.

**H-5. 화도(슬롯) 관리 재디자인 미적용** *(실측)* — 🔴급 승격 검토
- 货道管理 화면만 **기존 중국어 + 라이트 테마 + 청록 셀** UI가 그대로 남아, 재디자인된 한국어 럭셔리 다크 테마와 심각하게 불일치.
- 관리자가 결제설정↔슬롯관리를 오갈 때 시각적·언어적 단절 발생.
- **조치**: 6층×10열 그리드, 상단 액션(恢复/保存/返回), 설정값(货柜地址·层·列·XY刻度), 도구(编辑格子·显示编号·循环·全体测试)를 한국어 + 다크 테마로 전면 재디자인. **자판기 슬롯 프로토콜과 직결되므로 우선순위 높음.**

### 🟡 개선 (Medium) — 완성도/신뢰도

- **M-1. 접근성 대비**: 다크 배경 위 보조 텍스트(회색) 명도 대비 WCAG AA(4.5:1) 확인 *(스펙)*
- **M-2. 재고/품절 상태 표기 일관성**: "품절 임박" 등 배지 규칙·색상 통일 *(실측: 배지 확인됨)*
- **M-3. 오류 복구 카피**: 투출 실패 시 환불/재시도/직원호출 등 다음 행동을 명확히 *(스펙)*
- **M-4. 다국어 확장성**: 언어 모달이 있으나 실제 문자열이 i18n 리소스로 분리됐는지 확인(하드코딩 시 확장 곤란) *(스펙)*
- **M-5. 결제 QR/카드 가이드 접근성**: QR 위치·높이가 착석/휠체어 사용자 접근 가능 범위인지 *(스펙)*

## 3. 하드웨어 · 백엔드 정합성 (신규 프로젝트 필수 검토)

키오스크 앱은 UI뿐 아니라 **실제 자판기 제어**와 맞물립니다. VMMS 관리앱은 鑫之源(Xinzhiyuan) 자판기 API 및 메시지푸시(RabbitMQ 계열)로 연동되어 있으므로, 키오스크 앱도 동일 규격을 따라야 합니다.

- **슬롯/선반 모델**: UI의 슬롯번호·재고 표기가 실제 자판기 채널 구성과 1:1 매핑되는지
- **투출 프로토콜**: "투출 중/완료/실패" 상태가 자판기 하드웨어 이벤트(모터 구동, 낙하 감지)와 실시간 동기화되는지
- **결제 연동**: 결제수단(카드/QR/동전기)·거스름돈·통화 설정이 관리자 결제설정 화면과 실제 결제 모듈에 반영되는지
- **해상도/방향 확정**: 초기 "1920×1080 가로" → 이후 "1080×1920 세로"로 정정된 이력. **실제 장착 패널의 물리 방향·해상도 최종 확정 필요.**
- **오프라인 내성**: 네트워크 단절 시 로컬 큐잉/재전송, 화면 상태 유지 정책

## 4. 신규 프로젝트 권고 (다음 단계)

사용자 선택에 따라 키오스크 앱은 **관리앱과 분리된 신규 프로젝트**로 진행합니다.

**권장 스택** (VMMS와 일관성 유지 + 키오스크 특성 반영)
- React + TypeScript + Vite (VMMS와 동일 → 팀 학습비용↓)
- 상태관리: Zustand (VMMS와 동일)
- 타입/API 클라이언트: VMMS의 `src/types`·`src/api` 자판기 관련 타입을 **공유 패키지**로 추출해 재사용 검토
- 키오스크 특화: 고정 1080×1920 캔버스 + 자동 스케일, 터치 전용(마우스 hover 제거), 무조작 타임아웃, 화면 꺼짐 방지(Wake Lock), 전체화면/키오스크 모드

**초기 구조(안)**
```
kiosk-app/
├─ src/
│  ├─ screens/      # attract, shop, detail, cart, payment, dispensing, complete, fail
│  ├─ modals/       # deviceInfo, customerService, language, admin(payment-settings)
│  ├─ components/   # ProductCard, CategoryRail, BannerSlider, NumberPad ...
│  ├─ store/        # cart, session(타임아웃), machine(슬롯/투출)
│  ├─ api/          # 자판기 API, 결제, 재고 (VMMS 타입 재사용)
│  └─ i18n/         # ko / zh / en 리소스 분리
```

**다음 단계 제안**
1. 실제 장착 패널 **해상도·방향 최종 확정** (H/W 담당 확인)
2. 鑫之源 자판기 API·투출 이벤트 규격 문서 재확인 (`DOC/자판기 API문서.pdf`, `DOC/자판기 메세지푸시 API문서.pdf`)
3. Figma Make **AI 크레딧 복구/업그레이드** 후 디자인→코드 추출, 또는 신규 프로젝트에서 직접 구현
4. 위 🔴/🟠 이슈를 실기기에서 우선 QA

## 5. 요약

- 전반적으로 **화면 커버리지(구매 전 과정 + 예외/관리자)와 브랜드 톤은 완성도 높음.**
- 다만 **① 상품 카드 탭 상세 진입, ② 하단 상태바 탭** 은 실기기에서 반드시 재검증 필요(치명).
- 키오스크 특화 요소(**텍스트 하한, 배너 속도, 무조작 타임아웃, 관리자 인증**)는 보강 권장.
- 최우선 선결 과제는 **해상도/방향 확정**과 **자판기 API 투출 정합성** — UI가 실제 하드웨어와 맞물리는 지점.
